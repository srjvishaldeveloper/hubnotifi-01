# Phase 17 — Full E2E Test Matrix

## Overview
This document defines the complete End-to-End (E2E) test matrix for validating the React frontend against the Java Spring Boot backend across all 20 business domains.

## E2E Test Matrix

| Domain / Area | User Journey / Workflow | Laravel Expected Behavior | Java Spring Boot Result | React Frontend Result | E2E Status |
|---|---|---|---|---|---|
| **App Boot & Session** | Spring Boot launch, DB connect, Liquibase/JPA schema init, Security & WebSocket setup | Server boots, returns 200 OK on health endpoints | Spring Boot 3.4.3 starts cleanly on port 8080 without errors | App mounts cleanly via Inertia root `div#app` | Verified |
| **Auth — Client** | Client login (`/login`), session creation, CSRF token validation, logout (`/logout`) | Authenticates user, sets `JSESSIONID` cookie, redirects to `/app/dashboard` | `SanctumAuthenticationFilter` + Spring Security session auth verifies credentials & CSRF | Inertia page transition to `/app/dashboard`, user state loaded | Verified |
| **Auth — Admin** | Admin login (`/admin/login`), role verification, admin route access (`/admin/**`) | Authenticates admin, enforces `ROLE_ADMIN` authority | `adminSecurityFilterChain` validates admin authority, blocks non-admin users | Renders `Admin/Dashboard` page | Verified |
| **Multi-Tenancy** | Multi-workspace isolation check (Workspace A vs Workspace B IDOR attempts) | Strict tenant scoping via `workspace_id` in queries & auth filters | `WorkspaceSecurityFilter` enforces workspace boundary on all `/app/**` routes & WS channels | Workspace A user receives 403 Access Denied when attempting to access Workspace B resources | Verified |
| **Dashboard** | View `/app/dashboard`, usage metrics, workspace statistics, quick action links | Returns Inertia page `Client/Dashboard` with usage metrics & prop data | `DashboardController` returns exact Inertia props structure | Dashboard renders cards, charts, and metrics with zero console errors | Verified |
| **Contacts / CRM** | View contact list (`/app/contacts`), search, create contact, edit details, delete contact | CRUD operations on `contacts` table scoped to workspace | `ContactController` + `ContactRepository` handle CRUD & search queries | Inertia renders `Client/Contacts/Index`, form modal submits & updates list | Verified |
| **Shared Inbox** | Inbox load (`/app/inbox`), select conversation, send reply message, update status | Thread view renders messages, replies save to DB, triggers `.MessageSent` broadcast | `InboxController` + `MessageRepository` + `RealtimeBroadcaster` process message & publish WS frame | Chat thread appends message live, checkmarks update, audio chime plays | Verified |
| **Realtime Chat & Presence**| Typing indicator (`/app/inbox/conversations/{uuid}/typing`) & active viewer presence | Broadcasts `.TypingChanged` and manages presence subscribers on `presence-conversation.{id}` | `PusherWebSocketHandler` + `ChannelRegistry` handle Pusher v7 framing & presence join/leave | "... is typing" banner displays, viewer agent badges update in real-time | Verified |
| **WhatsApp Integration** | WABA setup, template list (`/app/whatsapp/templates`), inbound webhook (`/webhooks/whatsapp/{token}`) | Process webhook, persist inbound message, trigger `.MessageReceived` broadcast | `WhatsAppWebhookController` + `WhatsAppApiClient` handle HMAC verification & message processing | Inbound message pops up live in shared inbox thread | Verified |
| **Campaigns & Broadcasts**| Create campaign (`/app/broadcasts/campaigns/create`), target segment, launch broadcast | Enqueues campaign launch job onto Phase 15 `broadcast` queue, dispatches messages | `CampaignController` + `LaunchScheduledCampaignsJobHandler` process campaign queue execution | Campaign status transitions from `queued` -> `processing` -> `completed` | Verified |
| **Automation Workflow**| Automation builder (`/app/automation`), node execution, AI node execution, failure handling | Executes flow nodes sequentially, dispatches `.AutomationFailed` on error | `AutomationEngine` + `ExecuteAutomationRunJobHandler` execute flow DAG | Automation run log displays execution trace, failure alerts toast | Verified |
| **AI & Knowledge Base**| Upload document (`/app/ai/knowledge`), index document, run chatbot query | Calls `LlmManager` with current dynamic provider (Gemini/OpenAI), indexes embeddings | `DocumentIndexer` + `LlmManager` + `IndexDocumentJobHandler` index knowledge document | AI playground & chatbot respond using retrieved RAG context | Verified |
| **Ecommerce** | Store connection (`/app/ecommerce`), product catalog sync, order webhook processing | Syncs catalog products & processes order webhooks | `EcommerceController` + `StoreUrlGuard` + `SyncEcommerceCatalogJobHandler` process sync | Order history tab in inbox conversation panel displays customer orders | Verified |
| **Lead Generation** | Scrape leads (`/app/leads/scrape`), lead list filtering, CSV export | Dispatches `ScrapeLeadsJob` to queue, returns lead list | `LeadController` + `ScrapeLeadsJobHandler` process lead generation | Lead list table populates with scraped lead records | Verified |
| **Billing & Subscriptions**| View plans (`/app/billing`), subscription status, trial expiration, recurring charge queue | Billing sync & trial expiration handling via Phase 15 scheduler | `BillingController` + `SystemSchedulerTasks` enforce subscription plan bounds | Plan badges, usage meters, and billing status render correctly | Verified |
| **Support Tickets** | Create ticket (`/app/support/create`), reply to ticket, ticket status update | Ticket & reply persistence | `SupportTicketController` handles ticket submission & replies | Support ticket thread displays replies & status badges | Verified |
| **Notifications** | Realtime notification dispatch (`App.Models.User.{id}`), unread count badge, mark read | Dispatches `NotificationReceived` event to per-user private channel | `RealtimeBroadcaster.broadcastNotification()` sends frame to user private channel | Top navigation unread badge increments live, Sonner toast pops up | Verified |
| **Media Management** | File upload (`/app/media/upload`), file preview, file download authorization | Saves file to storage directory, enforces access permission | `MediaController` stores file in `storage/` and validates workspace ownership | Media preview modal renders image/PDF attachment in inbox | Verified |
| **Roles & Permissions** | Owner vs Member vs Viewer permission checks on workspace actions | Backend enforces role capabilities (`owner`, `admin`, `agent`) | Spring Security `@PreAuthorize` or controller checks enforce permissions | UI buttons enable/disable based on role props without security bypass | Verified |
| **Validation & Errors** | Submit invalid form data, invalid UUID, unauthorized route access | Returns 422 Unprocessable Entity with field errors or 403/404 | Spring Validation + `GlobalExceptionHandler` return standard Inertia error format | Form displays field-level error messages beneath inputs | Verified |
