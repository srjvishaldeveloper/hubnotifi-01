# Phase 16 — Realtime Security Audit

## Overview
This document outlines the security architecture, authorization mechanisms, tenant isolation rules, and threat mitigation strategies for the Java realtime migration.

## Security Boundary Principles

### 1. Authentication Required
- All WebSocket connection authentication and private/presence channel authorization requests **MUST** go through session/token validation.
- Anonymous / unauthenticated clients **MUST** be rejected at `/broadcasting/auth` with `403 Forbidden`.

### 2. Multi-Tenant Isolation
- **Workspace Isolation**: Users can only subscribe to `workspace.{workspaceId}`, `conversation.{conversationId}`, or `presence-conversation.{conversationId}` if `userCanAccessWorkspace(user, workspaceId)` returns `true`.
- **User Isolation**: Users can only subscribe to `App.Models.User.{id}` if `user.id === requested_id`.
- **Zero Cross-Tenant Leakage**: A user belonging to Workspace 10 **MUST NEVER** receive events broadcast to `workspace.20`.

### 3. Server-Side HMAC Signature Validation
When a Pusher WebSocket client requests channel subscription, the server verifies that the subscription auth signature presented by the client matches the signature generated by `/broadcasting/auth`:
`HMAC_SHA256(socket_id + ":" + channel_name, PUSHER_APP_SECRET)`

## Threat Analysis & Risk Mitigation

| Threat Vector | Description | Severity | Mitigation Strategy in Java Implementation |
|---|---|---|---|
| Unauthorized Channel Subscription | Malicious user attempts to subscribe to `workspace.999` without permission | High | Java `/broadcasting/auth` validates session user workspace membership before signing token. WebSocket server verifies signature before allowing channel subscription. |
| Socket ID Tampering | Attacker steals auth token for socket A and uses it on socket B | High | HMAC signature includes `socket_id`. Attempting to use signature on a different `socket_id` fails verification. |
| Event Injection (Whisper Hijack) | Client sends fake `MessageReceived` event over WebSocket | Critical | Disable client events / whispers in Pusher configuration. The Java server **only accepts client events for typing** via REST POST endpoints (`/app/inbox/conversations/{uuid}/typing`), never allowing clients to publish arbitrary JSON frames over WebSocket. |
| CSRF Attacks | Cross-Site Request Forgery on `/broadcasting/auth` | Medium | Validate `X-CSRF-TOKEN` header and standard Spring Security CSRF protections. |
| Session Expiration | User session terminates while WebSocket connection is active | Medium | Periodic connection ping/pong token check or session invalidation listener closes orphaned WebSocket connections. |
